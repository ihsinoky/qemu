# RX62N → RX113 差分表（fork-local 作業文書）

状態: v2（2026-11-05、PMO 作成。v1 の誤記と欠落を Issue #1 Worker の一次資料照合に基づき訂正）
方針・基準の採用は PO ゲート。本書は事実の整理と PMO 推奨までを含み、決定は含まない。

変更履歴:
- v2: コードフラッシュ基底の計算誤り（0xFFE00000 → 正しくは容量から算出、512KB なら 0xFFF80000）、HW マニュアル番号（R01UH0365EJ は RX111 用 → RX113 は R01UH0448EJ0120 Rev.1.20）、CMT／TMR のモデル構成の記述を訂正。v1 で欠落していた §4.2 後半〜§7 を復元。ICU の阻害要因（§3）を追記。

## 情報源と信頼度

- RX62N 側: 本リポジトリの実装そのもの（`hw/rx/rx62n.c`、`hw/rx/rx-gdbsim.c`、`include/hw/rx/rx62n.h`、`hw/intc/rx_icu.c`、各周辺モデル）。
- RX113 側: ルネサス公式製品ページ／型式別属性、RX113 用公式 iodefine.h（RSK サンプル同梱）、および **RX113 グループ ユーザーズマニュアル ハードウェア編 R01UH0448EJ0120 Rev.1.20**（Issue #1 Worker が公式 PDF を取得し ICU 章 §14 を照合。SHA-256 は Issue #1 報告書に記録）。
- iodefine.h はファミリ共通ヘッダである点に注意：ベクタ定義があってもアドレス定義のないモジュールは、原則として RX113 には実装されていないものとして扱う（SCI8/SCI9 の扱いは §7）。

## サマリ

| 項目 | RX62N（QEMU 実装） | RX113（実チップ） | 影響 |
|---|---|---|---|
| CPU コア | RXv1 | RXv1 | 共通。`target/rx/` は無変更でよい |
| FPU | あり（QEMU の rx62n CPU は softfloat 状態を持つ） | **なし**（全型式で Floating Point Unit = No） | CPU 型の扱いが差分（§1） |
| 最大動作周波数 | モデルは PCLK = XTAL×4、最大 50MHz | 32MHz | クロック前提を流用できない（§2） |
| RAM | 64KB（N7）/ 96KB（N8） @0x00000000 | 32KB / 64KB @0x00000000 | クラス定数の差し替えのみ |
| データフラッシュ | 32KB @0x00100000 | **8KB** @0x00100000 | 同上 |
| コードフラッシュ | 384KB / 512KB（N8 の基底 0xFFF80000 は末尾整列と一致） | 128/256/384/512KB、**末尾 0xFFFFFFFF に整列** | 基底は容量から算出する |
| 外部バス | あり（gdbsim は SDRAM を 0x01000000 に配置） | **なし** | マシン定義を流用できない（§5） |
| 割り込み | ベクタ 256 本、IPR は 142 までに収まる割付 | 最大ベクタ 249、**IPR 番号は最大 249** | **ICU モデルの拡張が必要**（§3） |
| モデル化済み周辺 | ICU / CMT / TMR / SCI（モデルあり） | 同種モジュールあり。CMT・TMR はモデル構成と互換、SCI はアドレス・ベクタが別 | §4 |
| RX113 固有の主要モジュール | — | LCDC、CTSU、USB0、S12AD、DAC、MTU、RTC、DTC、ELC 等 | スタブ方針＋LCDC は新規モデル（§4.2） |

## 1. CPU

- 両者とも RXv1 コアで、`target/rx/` の命令実装は共通に使える。
- 相違は FPU の有無のみ。既存 CPU 型に FPU 無効化の仕組みは確認できていない。RX113 向けファームは FPU 命令を含まない前提で当面は進め、厳密な制限（FPSW の扱い含む）は別途設計事項として §7 に残す。
- 割り込みモデル（ICU 経由の IRQ/FIR の受け方）は RX62N と同方式でよい。

## 2. メモリマップとクロック

| 領域 | RX62N モデル | RX113 |
|---|---|---|
| RAM | 0x00000000〜（64/96KB） | 0x00000000〜（32/64KB） |
| データフラッシュ | 0x00100000、32KB | 0x00100000、**8KB** |
| コードフラッシュ | N8: 0xFFF80000〜（512KB、末尾整列） | 末尾整列（512KB なら 0xFFF80000〜0xFFFFFFFF、256KB なら 0xFFFC0000〜） |
| 周辺レジスタ領域 | 0x00080000 台 | 0x00080000 台＋0x000A0000 台（USB/LCDC/CTSU） |
| 外部 CS 領域 | 0x01000000（gdbsim の SDRAM） | 存在しない |

- 型式クラス（抽象 MCU クラス＋型式別クラスで RAM/ROM/DFLASH サイズを持つ）は RX62N のパターンを踏襲する。コードフラッシュ基底は固定値にせず容量から算出する。対象型式の既定は D-003 のとおり **R5F51138（512KB／64KB／E2 8KB、公式 Table 1.3 で確認済み）** を製品 BOM と照合して確定する。
- クロック：RX62N モデルは「PCLK = XTAL×4（XTAL 8–14MHz）」を realize に埋め込んでいる。RX113 は最大 32MHz で前提が異なるため、RX113 側 realize で独自に定義する（周辺モデルへ渡す input-freq の決め方を含む）。

## 3. 割り込み（ICU）— 拡張が必要

- ICU の基本構造（IR/IER/IPR/DTCE の扱い、優先度解決）は流用できるが、**既存モデルの IPR 保持数は 142**（`include/hw/intc/rx_icu.h` の `uint8_t ipr[142]`、MMIO デコードも添字 0–143 の範囲、VMState も 142 要素）。
- RX113 の IPR 番号はベクタ番号と一致する範囲が広く、TMR=174、SCI0=214、SCI12=238、最大 249 に達する。実 IPR 番号をそのまま `ipr-map` に渡すと配列範囲外参照になる（Issue #1 で確認済みの阻害要因）。
- 対応方針（実装方式の選択であり、Issue #2 で実施）：**ICU の IPR 数をデバイスプロパティ化し、既定値 142 で RX62N の動作を完全に維持、RX113 では 256 を指定する**。MMIO デコード範囲と VMState はプロパティに追随させる。
- RX113 のベクタと IPR（公式マニュアル §14.3.1、Table 14.3 より。IPR はモジュール先頭ベクタと同番号で共有される形）：

| モジュール | ベクタ | IPR | 検出形式 |
|---|---|---|---|
| ICU SWINT | 27 | 3 | Edge |
| CMT0–3 | 28–31 | 4–7 | Edge |
| 外部割り込み IRQ0–7 | 64–71 | （Table 14.3 参照） | — |
| TMR0 / TMR1 / TMR2 / TMR3 | 174–176 / 177–179 / 180–182 / 183–185 | 174 / 177 / 180 / 183（3 本で共有） | Edge |
| SCI2 | 186–189 | 186（4 本で共有） | ERI/TEI=Level、RXI/TXI=Edge |
| SCI0 | 214–217 | 214（同上） | 同上 |
| SCI1 | 218–221 | 218（同上） | 同上 |
| SCI5 | 222–225 | 222（同上） | 同上 |
| SCI6 | 226–229 | 226（同上） | 同上 |
| SCI12 | 238–241、SCIX0–3 は 242–245 | 238（同上）、SCIX は 242–245 | ERI/TEI=Level、RXI/TXI=Edge、SCIX=Level |

- 参考（未モデル化モジュール）：USB0=36–38・90、CTSU=60–62、RTC=63・92・93、S12AD=102–103、MTU=114 から。最大ベクタは 249。

## 4. 周辺モジュール

### 4.1 既存モデルが流用できるもの

| モジュール | RX62N モデルの配置 | RX113 の配置 | 必要な変更 |
|---|---|---|---|
| ICU | 0x00087000 | 0x00087000 | アドレス同じ。§3 の IPR 拡張＋RX113 用 IPR 表・トリガ一覧 |
| CMT | 2 ユニット @0x00088000 / 0x00088010 | 2 ユニット×2ch。CMSTR0 0x00088000、CMSTR1 0x00088010、各ユニット内の ch 配置（+2/+8）もモデルの前提と一致（マニュアル §23、Table 5.1 で確認） | 実質そのまま 2 ユニット分を実体化。動作互換性の検証は実装時 |
| TMR | 1 インスタンスで 2ch、IRQ 6 本（ch ごとに CMIA/CMIB/OVI、出力順は ch0→ch1）@0x00088200 / 0x00088210 | TMR0–3 が同アドレス配置 | 2 インスタンスで 4ch。ベクタ 174–179 / 180–185 へそのまま配線可能 |
| SCI | unit 0 のみ @0x00088240、IRQ 順は ERI/RXI/TXI/TEI | SCI0 0x0008A000、SCI1 0x0008A020、SCI2 0x0008A040、SCI5 0x0008A0A0、SCI6 0x0008A0C0、SCI12 0x0008B300。IRQ 順は ERI/RXI/TXI/TEI でモデルと一致 | **アドレス帯が全く違う**＋ベクタは §3 の表引き。拡張レジスタと ch ごとの機能差（SCI12 の SCIX 等）の適合は実装時確認 |

### 4.2 RX113 にあって QEMU にモデルがないもの

SYSTEM 0x00080000、DTC 0x00082400、IWDT 0x00088030、DAC 0x00088040、MTU 0x00088600 台、S12AD 0x00089000、ELC 0x0008B100、CAC 0x0008B000、DOC 0x0008B080、RTC 0x0008C400、ポート／MPC 0x0008C000 台、USB0 0x000A0000、**LCDC 0x000A0800**、CTSU 0x000A0900。

方針（project.md の既定どおり）：まず `unimplemented-device` のスタブで領域を確保し、ファームのアクセス記録を見て必要なものからモデル化する。**LCDC は表示 RAM／セグメント状態を外部から読める形で新規モデル化する**（表示確認は画像ではなく状態でアサートする、という PO の既定方針に従う）。本表の段階では全てスタブ対象。

## 5. マシン定義 — 新設が必要（PO ゲート）

- 既存の gdbsim マシンは、外部 SDRAM（0x01000000）にカーネルを載せ、DTB を渡す Linux／GDB スタブ前提の構成で、MCU オブジェクト型も RX62NState に固定されている。外部バスのない RX113 には構造ごと合わない。
- PMO 推奨：**RX113 用マシンを新設する**。フラッシュへ `-kernel` の ELF（または `-bios`／ファームイメージ）を載せ、リセットベクタから実行する素直な組み込み向け構成。マシン名は型式ベース（例：`rx113-r5f51138`）を基本とする。
- 本節の採用は方針決定として PO ゲートに残す。MCU 定義（§2–§4）はマシンの選択に依存しないので先行できる。
